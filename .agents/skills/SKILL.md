# 嵌入式工程移植与开发规范

## 执行约定

此skill是工程实施规范。用户要求移植、开发或修改代码时，直接完成所指定范围的代码、构建与验证；不能只输出规范性检查报告。用户仅讨论方案时不擅自重构。

本规范同时约束首次迁移和此后的新增、修复、重构。用户明确要求将规范应用到目标工程时，执行：

```bash
python3 <本skill目录>/scripts/install_project_rules.py --project <目标工程> --scaffold
```

该脚本安装工程内规范与根AGENTS受管区块，不搬动业务代码。**安装规范不代表完成移植**；随后必须落实本次要求的实际模块迁移。更新已安装规范使用`--update`，脚本先备份被替换文件。后续小修改按工程内规范执行，不反复安装或全量搬目录。

目标工程已有更高优先级指令或用户明确约定时遵守它们，并显式记录目录/API映射。禁止默默混用两套命名体系。不要把当前IDE目录当作用户指定目标。

## 工作顺序

1. 确认目标MCU、编译器、构建配置、源文件清单、外设映射、RTOS/裸机模式及当前可运行基线。保留原API/二进制兼容要求；迁移前保存源码及构建配置。
2. 阅读下列实施规范。迁移先整理职责与依赖，再逐模块移动/适配，更新include、构建、初始化和调用方。迁移与控制参数/算法变更分开。
3. 保留已验证驱动的真实协议、寄存器及时序，迁移其平台依赖与实例边界。缺少结构时使用`assets/templates/`中的可编译实例补齐端口、状态和诊断；新驱动须替换真实协议、设备ID和板级IO，不得把示例协议当作硬件实现。
4. 实际接入唯一生效的实现；不保留两套任务同时操作同一外设。兼容旧接口时使用标明边界的薄适配层，不能静默改旧返回值含义。
5. 为修改后的接口、错误路径和状态迁移完成必要验证，核对目标配置构建、链接资源和已知未实测项。不得把“修改了目录/规范”当作功能已迁移完成。

## 必须遵循的规则

### 分层与命名

按[分层与命名](references/layers-and-naming.md)组织`AA_app / AB_service / AC_module / AD_platform / AE_common / AF_config`。新建/迁移模块遵守目录、文件、类型、函数、宏、变量和include规则。保留厂商及代码生成器管理的目录名称。

- 应用编排业务，服务管理能力与资源，驱动处理设备协议，端口处理MCU/OS，公共层保存不依赖业务的基础能力。
- 驱动通过带类型的IO/时间接口和context绑定平台；wrapper提供设备能力，adapter负责绑定和错误转换。按需要保留handler，不为一个转发动作增加一层。
- 纯驱动和算法不包含HAL/FreeRTOS/应用头；adapter只调用已声明的平台端口，组合根负责注册。禁止散落手写extern或不兼容函数指针强转绕开依赖。
- 公共API有模块前缀和明确单位；私有实现使用static。不能在通用执行器里通过计划ID/相邻步骤顺序猜测业务动作。

### 中文Doxygen接口

按[接口与编码规则](references/interfaces-and-c-style.md)实现。**新增、迁移、修改涉及的.h公共接口必须补全中文Doxygen**：文件、类型、枚举值、字段、函数指针和函数声明均有可读说明。

函数说明必须给出`@brief`、带方向的`@param`、返回语义及实际错误`@retval`；按接口性质注明单位/范围、阻塞上界、上下文、线程安全、数据寿命、失败后输出有效性与初始化前提。无参数/无返回值不伪造标签。只有英文解释、只有.c注释、只有“成功/失败”均不达标。

### 错误处理与FSM

按[错误码与状态机](references/errors-and-fsm.md)实施。

- 失败不能只返回`-1/false/ERROR`；保留稳定的符号错误码和底层原因，提供错误名与中文描述查询。布尔谓词和纯数值计算可按自身语义返回，不强制包装成功码。
- **每条进入FAULT/ERROR终态的路径必须经模块统一失败入口**，记录终态原因、底层原因、失败前状态/阶段、请求ID、时间、文件、函数、行号；未知状态default也须有专用错误码。
- 最后错误可通过状态/结果API读取，不依赖printf；清理错误另记，不能覆盖首个业务失败原因。
- 正常等待、无新数据、取消与故障区分；请求接受、设备ACK、反馈完成、预计时间结束和结果未知分别表达。
- 重试有总预算；不能盲目重发可能已执行的非幂等命令。驱动报告事实，应用选择局部重试、替代、跳过或终止。

### 实时、并发、配置与构建

按[运行时与工程集成](references/runtime-and-build.md)实施。模块声明状态/资源归属、执行上下文和等待预算；长动作非阻塞分步，初始化和短事务可有界阻塞。模块不默认对应一个RTOS任务。

ISR/DMA、锁、取消代际、日志背压、内存与栈预算都属于实现约束。板级、设备、标定、控制和任务配置分别管理；生成输入是权威源，不能靠改生成输出维持行为。

## 模板和持久约束

- `assets/templates/AE_common/fw_error.*`：统一错误注册表、中文说明、失败位置记录。
- `assets/templates/AC_module/sample/driver/`：类型化端口、独立实例、中文接口注释及可定位终态的分步驱动。
- 模板按当前命名直接可编译；复制到目标后按真实模块重命名，登记新的模块ID/错误码，更新调用和构建。已有兼容公共错误体系时适配并补齐诊断，不强行破坏ABI。
- 用`scripts/test_templates.py`验证模板与规范安装行为。实际项目还须链接移植后的生产实现验证，模板通过不能替代目标验证。
- 根AGENTS指向工程内规范，后续agent无需本机skill路径也能读取规则。已有AGENTS的其他内容必须保留。

交付实际变更、可调用API、构建/测试结果及尚未连接的硬件依赖；不要以“检查到若干问题”结束移植任务。此skill不自动授权烧录、复位或运动。
