# 运行时、并发与工程集成

## 时间与资源

- 任务在组合根统一注册周期、优先级、栈大小及栈单位；服务不暗中创建后台任务。同一外设/执行器只由一个仲裁者提交命令。
- 长动作用`start/step/cancel/get_result`等非阻塞生命周期；有预算的初始化、短总线事务、低优先级诊断可同步等待。等待必须有总上界。
- 周期任务使用明确的周期调度，处理超期并记录计数，不无界追赶。每次step包含锁等待、下层事务、重试、回调与日志背压的整体预算。
- 不持状态锁等待设备、sleep、做不确定耗时格式化或执行未知回调；需要持有总线锁的短事务记录上界。多锁给出顺序；拆锁后提交仍校验请求代际。
- 物理STOP、软件取消、资源清理有明确顺序；停止不能先被长流程锁阻塞。驱动器保持最后命令时，需要相应TTL、故障停止或独立保护，而非假定任务永远存活。
- 跨线程/ISR数据使用原子、临界区或一致快照；volatile只保证访问语义。快照注明字段有效性、来源时间和序号。
- 数据缓冲、动作表与队列有容量及溢出策略。堆按生命周期使用，实时热路径不得无说明地分配；初始化失败释放已获得资源。
- 检查Flash、静态RAM、运行期堆、栈最低余量和最长服务时间。单函数stack-usage不能代表全部调用链和中断/浮点上下文。

## ISR、DMA和日志

- ISR只承担必要硬件服务、搬运、时间戳与通知；按平台核对FromISR接口和中断优先级，不在ISR中取普通mutex或进行等待式IO。
- DMA缓冲区说明复制/借用和复用时机；核对对齐、DMA可访问内存和cache。半双工区分DMA完成与UART TC，不提前切接收。
- abort后清理硬件状态和晚到回调；老事务的中断不能推进新事务。
- 日志采用有界提交、输出优先级和队列满策略；错误记录先写模块状态，再尝试日志，不因日志失败丢失原错误。实时路径不能无限等调试器。

## 构建与配置

- 公共头单独可编译，模块私有头不在全工程全局include暴露。按模块登记源和include，依赖关系在构建中可见。
- 生成器托管文件只改生成输入和允许的USER CODE；不同时保留两个IRQ/回调所有者或重复任务注册。
- 平台/OS配置、设备规格、标定、控制参数和任务表分别具有权威源；多板/多设备通过adapter和配置选择实现，不用大段业务#ifdef复制两套算法。
- 保留目标工具链/链接脚本/启动文件/外设映射，迁移不顺带升级SDK或改时钟。需要改变时分开实施并核对计时和通信参数。
- 已发布API/配置格式/错误码ABI不能静默改变；用兼容层和显式映射，替换完成后再删除旧实现。

## 持续修改与验证

已安装的工程内规范对后续修改持续生效。小修复只改变必要代码，但涉及的接口补齐中文Doxygen、错误码和输出契约。用户明确要求调整参数时执行参数修改，不扩成全工程重构。

测试链接生产源与真实公共头，关注状态迁移、时间、取消、结果和错误定位；不复制一个简化算法后用它自证。用空mutex替身的单线程测试不能证明并发安全。

在可用目标配置下构建并检查链接占用；必要时ASan/UBSan及主机故障注入。真实RTOS时序、DMA和物理动作单列实测，不拿编译或模板测试代替。没有工具链/硬件时准确列出未验证部分，不假造通过。
