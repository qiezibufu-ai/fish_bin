# 嵌入式工程代码规则

本目录中的规则适用于工程移植，以及此后的功能开发、修复和重构。实施任务必须完成指定范围的实际代码和构建接入，不能以只做规范检查代替。

进行嵌入式代码修改前，读取：

1. [分层与命名](layers-and-naming.md)：目录、文件、API、类型与依赖。
2. [中文Doxygen与编码](interfaces-and-c-style.md)：.h中文接口契约、数据寿命和编码细节。
3. [错误码与FSM](errors-and-fsm.md)：错误身份、底层原因、错误位置和终态。
4. [运行时与构建](runtime-and-build.md)：并发、IO、实时预算和工程集成。

必须执行：新增/迁移/修改涉及的公共头文件补齐中文Doxygen；所有FSM错误终态有具体可读错误码与文件/函数/行号；错误原因不能在包装或清理中丢失；模块按约定分层和命名。

每次修改只处理用户要求范围。保留厂商/生成目录与公开兼容约定；目录和API确需映射时，在本工程记录其权威映射并同步构建和调用方。规则不能成为擅自改控制参数、重复启动资源、烧录或运动的依据。
